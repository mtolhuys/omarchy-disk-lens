# Roadmap

## M0 — Product foundation — complete

- Authoritative product, UX, architecture, security, dependency, test, and release contracts.
- Public README, contribution, support, security, changelog, and license files.

**Evidence:** the English-only documentation and repository-contract checks pass in `make test`.

## M1 — Honest vertical slice — complete

- Valid Omarchy manifest with working service and bar-widget entry points.
- Theme-native proportional pie gauge, capacity rail, and panel.
- Strict capacity and scan adapters.
- Synthetic immediate-child scans, source tests, and loaded build identities.

**Evidence:** a real QMP pointer opens the panel in the Plugin Lab and exact synthetic totals reach the loaded widget state.

## M2 — Visual analysis and filters — vertical slice complete

- Shared result and selection model.
- Ranked list and squarified treemap.
- Parent navigation, drill-down, search, type/hidden/size/age filters, inspector, and explicit empty/partial/error states.
- Cancellation and last-good-result preservation.
- Dark and light theme review, long-scope fixture, empty fixture, and permission-failure fixture.

**Remaining release work:** dense 5,000-entry visual acceptance, narrow layouts, warning/critical/unknown capacity fixtures, quantified idle/scan/cancellation budgets, composed-panel reduced-motion acceptance, complete keyboard traversal, focus review, contrast measurements, and assistive-technology acceptance.

## M3 — QDirStat bridge — directory hand-off complete

- Optional executable detection and live re-detection.
- Explicit missing-dependency card and visible terminal action using `omarchy pkg aur add qdirstat`.
- Selected-directory launch through a structured process argument.
- Disposable-guest AUR package installation and mapped-window acceptance.

Package, unpackaged-file, and cache-file views are deliberately not implemented in `0.3.0`; each requires a separate literal product contract before it can ship.

## M4 — Selected-folder agent guidance — complete

- **Ask Omarchy** is limited to actionable selected directories.
- Exact path and allocation are passed through the maintained `omarchy agent prompt` contract.
- The fixed prompt requires a read-only investigation and an explicit confirmation boundary.
- Disposable-guest acceptance uses a default-agent shim to capture the full argument without host credentials or provider access.

## M5 — Release hardening — in progress

Completed:

- clean committed runtime candidate with exact Plugin Lab evidence;
- same-path runtime update identity;
- enable, disable, re-enable, and removal cleanup;
- exact-working-tree development installation;
- synthetic screenshots and light/dark review;
- source, installed, and loaded identity assertions;
- purposeful live scan activity with static status equivalents;
- deterministic current-product README showcase and media provenance contract;
- stricter bounded scanner-protocol validation and optional ShellCheck coverage;
- removal of completed planning and placeholder documentation.

Still required for a public release:

- version tag;
- reproducible distribution artifact and SHA-256;
- clean-clone installation on the declared minimum Omarchy version;
- quantified performance and accessibility gates;
- final release notes and owner publication approval;
- owner-authorized push, tag, release, and marketplace submission.

## Later, only with evidence

- Compatible QDirStat cache exchange to avoid duplicate scans.
- Btrfs-specific allocation and snapshot explanations.
- Saved scan scopes or bounded persistent cache.
- Explicit package or unpackaged-file entry points.

These are not version `0.3.0` promises.
